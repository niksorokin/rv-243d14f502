03 · PATTERNS

What repeats across everyone.

Six patterns visible in the data for all six participants. These are not one-off tasks, but structural losses that repeat every week.

01

Messengers are the team work layer

Telegram + WhatsApp total more than 600 minutes per week across the six people. Decisions are made in chats and then manually transferred into trackers, sheets, Fleet, and dashboards. This duplication is a constant cost line.

02

Dashboard → text → dashboard is the shared loop

Most of the six move from Metrics / the tracker / Sheets into messages and back. The most expensive part of the loop is turning data into text: metric descriptions, team takeaways, and exception alerts.

03

Meeting follow-up piles up

Marco has 8+ meetings, Daniel has country Zooms, and Omar Farouk has team calls. Notes after each one are handled manually, and follow-up gets lost or delayed. This is not a one-time issue; it repeats every week.

04

Context is lost during switching

Countries, projects, ventures, and operating systems: each participant switches between 8-20 contexts during the day. Rebuilding context after a switch is an expensive operation for the whole team.

05

Ad-hoc data requests break focus

Tomas gets one-off data-pull requests straight into Slack/Telegram, while Priya assembles channel reports by hand. Every request is a context switch and lost focus; the same pulls repeat week after week.

06

Design↔code loop and content repurposing

Lena runs the Figma → Cursor → live-preview loop with manual screenshot export, while Priya repackages the same content for every channel. The creative work is there, but the scaffolding around it is repeatable manual busywork.

01 Team digest from Telegram and WhatsApp 90-120m/week Coordination Start now
Description

Every morning, one digest across the key chats: decisions, unanswered questions, tasks without tickets, owners, and deadlines. Important: not a general recap, but an action queue for Marco as the lead and for each team participant.

Signal

Messengers remain the main work layer: Marco has 50+ Telegram chats, Daniel has 30+ contacts and 310m in Telegram, and Omar Farouk has ~105m in WhatsApp/Telegram for Egypt Ops. Decisions are born in chats, but then they are manually moved into Tracker, Sheets, Fleet, and follow-up messages.

Tools

Telegram Bot API, BotFather, WhatsApp Business export/manual paste for the pilot, Cloudflare Worker or Railway, Claude/OpenAI, the tracker (Linear) API, Google Sheets for the decision log.

How to implement
  1. Create a Telegram bot via BotFather and a closed team chat #team-digest.
  2. During the first week, do it without APIs: participants forward important messages to the bot or a separate chat; the Worker saves them to Google Sheet.
  3. Write a Claude/OpenAI prompt: classify messages into decisions, questions, tasks, FYI, and risk; required fields are owner, source, and next action.
  4. Connect the tracker (Linear): create tasks above the confidence threshold as drafts/comments, not automatically in production.
  5. Pilot on 3 chats: Driva mobility, Egypt Ops, Vitae/Nova; expand after one week.
First step

On Monday, create the bot and one closed chat where the whole team forwards only messages that require action.

What disappears
  • manual morning review of dozens of chats in sequence
  • searching for “where did we decide this”
  • manual assembly of the follow-up list after chats
  • lost tasks that were mentioned in chat but never reached Tracker
ROI

Pilot build: 1-2 days. Savings: 1.5-2 hours per week across the six people. Break-even: 1-2 weeks.

04 Chat → tracker (Linear) without manual transfer 45-65m/week Tracker High priority
Description

Decisions and tasks from chats become draft Tracker tickets or comments. A person approves them, but no longer rewrites the context, owner, and source-message link by hand.

Signal

For Daniel, Telegram decisions move into Tracker/Sheets for Mexico, Kenya, Bogotá, Hanoi, and FleetHub. For Omar Farouk, WhatsApp/Telegram lead into Fleet, Sheets, and support trackers. For Marco, Driva/Vitae/Nova decisions often live in chats.

Tools

Telegram Bot API, the tracker (Linear) API, Google Sheets audit log, Claude/OpenAI classifier, optional browser extension/bookmarklet for copying the source link.

How to implement
  1. Add a /task command in the team bot: forwarded message + short comment.
  2. The classifier determines queue, summary, owner, deadline, project, and confidence.
  3. When confidence is < 80%, the bot asks a clarifying question instead of creating a ticket.
  4. On approval, it creates a draft ticket or comment in the relevant the tracker (Linear) queue.
  5. Every Friday, the bot sends a list of created and rejected tasks to calibrate the prompt.
First step

Run a manual pilot: process 10 forwarded messages from the week through the prompt and compare them with the tickets that are actually needed.

What disappears
  • copying text from chat into Tracker
  • writing title/description from scratch
  • then searching for the source discussion link
  • creating tasks from memory a day later
ROI

Pilot build: 2 days. Savings: 45-65 minutes per week. Break-even: 2-3 weeks.
